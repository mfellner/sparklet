# Working in this repository

Sparklet is one app of the multi-app platform for the **Waveshare ESP32-C6-Touch-AMOLED-2.16** defined in [mfellner/esp32-playground](https://github.com/mfellner/esp32-playground). Device rules, the flash layout, the launcher and the board-generic documentation live there. Before any hardware work, read the platform's [AGENTS.md](https://github.com/mfellner/esp32-playground/blob/main/AGENTS.md), [hardware](https://github.com/mfellner/esp32-playground/blob/main/docs/hardware.md), [interaction](https://github.com/mfellner/esp32-playground/blob/main/docs/interaction.md) and [recovery](https://github.com/mfellner/esp32-playground/blob/main/docs/recovery.md) notes, and use its [esp32-c6-waveshare skill](https://github.com/mfellner/esp32-playground/blob/main/skills/esp32-c6-waveshare/SKILL.md) for USB/firmware tasks. Those rules apply here unchanged.

- Discover the board with `uv run scripts/esp32_serial.py list` (kept here for Sparklet's validators and release bundles); select only the known USB identity documented by the platform.
- Never use `idf.py flash` or `idf.py app-flash`; they would overwrite the launcher and reset the boot selection, and the project's platform guard makes them fail. Flash with `idf.py -p PORT sparklet-flash` (writes only `build/sparklet-flash_args`, the `sparklet` slot at `0x220000`) or `uv run <esp32-playground>/tools/device.py install sparklet firmware/sparkdash/build`.
- `firmware/sparkdash/partitions.csv` and `sdkconfig.defaults.platform` must stay byte-identical to the platform's `components/app_switch/layout/` copies; configuration fails otherwise. Change the layout in the platform repository first, then copy it here.
- The board (`mfellner/board`) and launcher client (`mfellner/app_switch`) are platform components. For local component development `main/idf_component.yml` may use `override_path`; commits must use the pinned git version.
- Keep credentials and raw flash/log data in ignored local files. Commit only reviewed, relevant diagnostic excerpts. Distinguish observed device facts from untested procedures.

The ESP-IDF project is `firmware/sparkdash`, pinned to SDK v5.5.3 at `/Users/max/esp/esp-idf-v5.5.3`. Activate its `export.sh` before builds; verify SDK availability rather than assuming it in a new environment. Python and uv are available; helper dependencies are declared in each script. Read `docs/sparkdash-validation.md` for completed and outstanding gates. The user excluded the 24-hour soak from v1 completion. Test-only USB controls are compiled out of normal releases.
